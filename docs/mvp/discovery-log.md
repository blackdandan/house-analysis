# MVP Discovery Log

## Conversation Summary

2026年6月10日，用户发起房产可视化系统的需求讨论。产品经理（Agent）与用户针对“杭州房地产信息可视化系统”的目标用户、核心使用场景、大盘与局部的数据构成、指标字段、展示布局进行了深度对齐。

## Key Questions And Answers

| Question | User Answer | Product Interpretation |
|---|---|---|
| 杭州局部数据的痛点和核心场景是什么？ | 贝壳数据太杂不够聚焦杭州；缺乏多小区跨盘对比；缺乏同比和环比数据；无法分析同户型在不同小区的偏好。希望有直观的杭州地图，放大能点到小区看成交量价，图表可自主切换。 | 局部价值闭环是：杭州地图找房/搜房 → 点击加入对比 → 渲染两个小区的成交价折线图、成交量柱状图、户型构成饼图 → 展示同环比。 |
| 大盘（全国70城）有哪些核心指标？ | 1. 70城二手房/新房均价指数（环比以100%为基准线，同比折线图）。<br>2. 某月70城价格环比涨跌幅柱状图。<br>3. 二手房成交套数及环比折线图。<br>4. 全国新房总销售面积与销售额。<br>5. 供给/需求端的一系列宏观经济指标。 | 大盘主要提供宏观周期研判。图表需要支持同环比展示。由于指标多且更新低频，将统一提供录入后台。 |
| 大盘宏观指标多且更新低频，如何低成本录入？ | 接受 PM 建议，MVP 阶段不写宏观爬虫，大盘数据通过“本地 Excel 上传导入”或“管理员后台表单”录入。 | 爬虫研发精力 100% 聚焦在每日更新的“杭州小区成交数据”抓取上，大盘数据录入走文件解析模式。 |
| 户型与楼栋的数据分析粒度如何控制？ | 接受 PM 建议，首期先支持标准化户型大类（一居、二居、三居、四居及以上），细颗粒度楼栋与户型朝向放至 P1 或 Later。 | 避免早期爬虫解析非结构化交易文本的极高成本，聚焦标准大类的买方偏好对比。 |
| 杭州成千上万个小区在地图上全部打点，导致卡顿如何解决？ | 接受 PM 建议，地图采用“按行政区/板块聚合”的机制，放大到一定层级才打点具体小区。 | 优化前端渲染性能与交互直观度。 |

## Scope Decisions

| Decision | Reason | Confirmed By User |
|---|---|---|
| 大盘宏观数据通过 Excel 导入 | 避免抓取不同宏观机构网站带来的高昂维护成本，这部分数据更新频率很低（按月/按季）。 | 是 |
| 户型归纳为“一/二/三/四居+” | 统一标准化维度，简化一期爬虫解析和对比计算逻辑。 | 是 |
| 地图打点引入“区级/板块级聚合” | 确保在成千上万个小区数据量下，前端地图页面能够流畅渲染，不发生卡顿。 | 是 |
