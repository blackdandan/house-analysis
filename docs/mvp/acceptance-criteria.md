# Acceptance Criteria

本文件详细记录“杭州房地产信息可视化系统”的产品验收标准，指导开发验证及最终交付评测。本文件不涉及技术底层实现验收。

## Product Acceptance Criteria (产品功能验收标准)

| ID | Requirement (产品需求) | Given (前提条件) | When (触发动作) | Then (期望业务表现) |
|---|---|---|---|---|
| **AC-101** | 70城指数环比走势以 100% 为水平基准线。 | 用户在大盘页面，70城指数趋势图（折线图）已渲染完毕。 | 用户点击“环比涨跌幅”切换按钮。 | 折线图横轴显示月份，纵轴在 100% 刻度处呈现一条醒目的水平基准参考线，折线展示各月指数围绕 100% 上下波动的相对趋势。 |
| **AC-102** | 全国新房销售双轴展示。 | 用户在大盘页面浏览“销售规模”板块。 | 页面加载完成或用户选择特定年份。 | 图表区域同时渲染两个刻度轴：左轴柱状图表示全国新房累计销售面积（万㎡），右轴折线图表示对应的同比增速百分比 (%)。 |
| **AC-103** | 分城市大盘指标快速检索。 | 用户在大盘页面“分城市表现”板块。 | 用户在城市检索下拉框中输入/选中“杭州”，并切换“二手房”类别。 | 系统即时更新并展现杭州最近 36 个月的二手房价格指数走势，且下方表格同步更新该城市一二线二手房月成交套数。 |
| **AC-201** | 杭州地图行政区到小区的无卡顿层级缩放。 | 用户在局部杭州地图页，地图层级为全市概览（Level 11）。 | 用户使用滚轮或双击放大地图，使缩放级别达到区域/板块级（Level 14 以上）。 | 1. 自动隐藏行政区聚合气泡；<br>2. 渲染出范围内具体小区散点；<br>3. 地图平移和缩放交互无明显视觉卡顿或帧率骤降。 |
| **AC-202** | 地图选盘一键加入全局对比。 | 用户在地图上点击了特定小区（如“学雅苑”）的散点。 | 1. 系统滑出右侧小区信息抽屉；<br>2. 用户点击抽屉底部的“加入对比”按钮。 | 1. 按钮状态变更为“已加入对比”；<br>2. 右上角悬浮对比池的计数即时 +1；<br>3. 用户切换至“小区对比”页时，该小区已预载在对比列表中。 |
| **AC-301** | 跨小区标准化户型量价同环比分析。 | 用户在小区对比页面添加了 2 个对比小区（如“学雅苑”与“翡翠城”）。 | 用户筛选户型为“三居”，对比时间选择“近1年”。 | 1. 均价趋势图正确展示两个小区近一年月度三居室均价；<br>2. 核心数据表展现两个小区的最新三居单价，并准确计算输出同比去年同期 (%) 和环比上月 (%) 波动数值。 |
| **AC-104** | 大盘看板折线数据悬浮交互 (Tooltip)。 | 用户在大盘页面浏览折线图（如70城指数）。 | 用户将鼠标指针移入图表区并在折线上滑动。 | 系统即时捕获鼠标坐标，自动高亮最邻近的数据点（渲染高亮圆圈），并在鼠标右上方滑出一枚带高透磨砂阴影的 Tooltip 卡片，精确呈现实时月份、指标值与同比/环比浮动百分比。 |
| **AC-302** | 对比看板图表类型的自主切换与强联动。 | 用户正在浏览对比小区的成交均价与套数走势折线图。 | 用户点击图表上方的“切换为柱状/饼图”按钮。 | 1. 均价/套数走势图即时切换为并排对比柱状图；<br>2. 切换为饼图时，展示对比小区的一/二/三/四居及以上标准户型的历史成交总套数占比，数据与折线模式保持 100% 一致。 |
| **AC-303** | 跨小区对比支持 3-4 个小区的自适应对比。 | 用户在对比页面选择了 3 个以上小区（如“学雅苑”、“翡翠城”与“武林壹号”）。 | 用户点击对比筛选或切换图表。 | 1. 图表区能够同时展现出多条折线（如 3 条不同颜色折线）或多组并列柱状图；<br>2. 下方的对照表格自动拓展为 3 列数据区，自适应对齐。 |
| **AC-401** | 管理员大盘数据 Excel 导入校验。 | 管理员在数据后台，准备上传最新的月度宏观数据。 | 管理员选择本地填报好的 Excel 文件并点击“上传导入”。 | 1. 系统自动验证文件结构与字段（70城指数、贷款、新开工等）；<br>2. 格式正确时，弹出“导入成功”并更新前台数据；<br>3. 格式有误时，红字报错，数据不写入且不影响前台展示。 |

## MVP Completion Criteria (MVP 完工验收标准)

1. **功能完整度**：所有 P0 级功能均已按照产品文档完成技术开发，并成功接入系统。
2. **数据流打通**：杭州小区级数据每日自动爬虫抓取管道畅通，且格式完全标准化；大盘 Excel 上传与数据解析器稳定运行，且在上传后能无缓存延迟地渲染到大盘看板。
3. **视觉 Preview 交互验收**：视觉预览页面 (`preview/mvp/`) 的 4 个核心页面（大盘、地图、小区对比、后台）完全拆分文件实现，且能在不部署服务器、不依赖外网 API 的环境下通过双击 `index.html` 直接完美运行，图表和地图缩放交互流畅度达标。
4. **决策确认落盘**：开发完成后，与用户进行最终视觉 preview 评审，并在 `discovery-log.md` 记录用户最终定稿确认，结束 Workflow。

## Non-Acceptance Conditions (拒收判定标准)

1. **图表数据不一致**：当用户切换折线图、柱状图和饼图时，同一个小区在同一个时间段内同一户型的均价和成交套数数值前后不一致，或者计算出来的同环比增幅百分比不正确。
2. **空状态体验崩溃**：当对比的两个小区没有重合户型成交（如一旧一新）时，图表渲染区域直接报错报错、显示为一片空白、或控制台发生 JavaScript 异常阻碍其他操作。
3. **数据导入损坏前台**：管理员上传了包含格式错误或缺失字段的 Excel 时，前台已有的历史大盘数据被覆盖为空、或者大盘图表发生解析错误导致页面无法渲染。
